# ACMCoder 统一产品设计

日期：2026-09-30

状态：用户已认可产品方向和 Gemini + 液态玻璃交互草图；本文整理已确认需求，并提出交付拆分供审阅。不是生产功能完成声明，也不是详细实施计划。

## 1. 目标与使用体验

提供桌面 ACM 手撕练习工具：获取题目 → 自己写完整程序 → 运行自测 → 立即重新手撕 → 查看原代码对照 → 可选隔天复习。

网站、本地 Web 和浏览器插件使用一致的核心规则和产品版本。插件是完整的侧栏练习入口；用户在 LeetCode 页面就能练习，不需要部署本地服务、先登录网站或一直打开网站标签页。

主要面向桌面操作。不为手机编程额外设计产品流程。不增加函数式练习，不优先建设截图/PDF 识别、公共社区或排行榜。

## 3. 界面设计

已认可参考：会话交互草图 `acmcoder-workspace.html`，位于当前会话的可视化目录。草图采用示例数据；Python 执行、AI 和导入响应均为演示，不能直接当作真实应用。

- 外观：Gemini 风格蓝紫渐变、液态玻璃导航和容器、圆角、柔和光影；支持明暗主题。代码区使用稳定的背景和足够对比度，避免透明效果干扰阅读。
- 导航：今日、题库、练习；账号与设置入口补齐。草图首先展示今日页用于审阅，不代表已经确定真实产品首次首页。
- 今日：继续上次练习、到期复习和新题推荐；可调整题量、标记完成，直接进入对应题目。
- 题库：我的题库、推荐题目、归档；搜索、导入、练习、归档与恢复。导入失败不能清空用户输入。
- 练习：左侧题面和样例，右侧代码，下方测试输入和结果；AI 按需展开；保存状态可见。
- 插件：LeetCode 原页面承担题面展示，侧栏主要用于代码、自测、AI 和重写；提供进入网站继续练习的入口。
- 对照：网站/本地左右查看新旧代码；插件切换查看，必要时进入网站展开。

建议真实产品默认恢复上次所在位置，无记录时提供可直接运行的示例；此为实现默认值建议，不冒称用户曾明确选择首页。

## 4. 作答、执行与重写规则

### 日常练习

按题目和语言保存当前草稿，包括代码、标准输入、期望输出。切题、退出、刷新后恢复。用户不需要管理“轮次”概念或点击保存。

仅根据实际执行的测试报告结果。导入公开样例的题目显示“样例通过”，不能表示原平台隐藏测试 AC；输入输出协议可编辑。原始函数参数样例不直接冒充 ACM stdin。

### 重新手撕

1. 点击后先可靠保留旧代码及对应输入，再创建最小模板草稿；保存失败时保持原编辑区。
2. 重写时默认隐藏旧代码，用户可主动展开。
3. 切标签页、切题、刷新或关闭浏览器后仍可恢复未完成重写。
4. “放弃本次重写”明确丢弃这份临时草稿，保留先前记录；普通关闭面板不等于放弃。
5. “结束并对照”保留新旧内容，不要求额外的完成概念，也不强制必须先运行通过。

无需保存每个按键为历史版本，也不把每次运行都强制做成永久代码快照。最低要求是最新草稿可恢复、重写前后记录可对照。

## 5. 数据与同步边界

数据至少区分：题目、按题/语言保存的草稿、重写快照、复习安排、偏好。实现时沿用可复用的现有数据结构，另行明确旧版迁移映射。

- 未登录：写入当前设备；插件和网页的存储彼此独立，未实现显式传递前不能声称天然共享。
- 已连接账号：本地先保存，再同步云端；断网保留待同步数据，恢复后继续。
- 首次连接：将本地内容合并到账号，冲突保留双方，不能静默覆盖。
- 多设备：使用记录标识和版本检测冲突；不能以“最后请求到达”覆盖另一端未保存内容。
- 归档：移出日常列表，保留题面和关联记录，可以恢复。
- 彻底删除：明确影响范围，删除云端对应内容，并让连接设备在下次同步时获知删除，避免离线旧副本自动复活。
- 数据长期保留：不得用时间或最近 N 条策略悄悄淘汰用户记录；容量不足时明确限制新增或提示导出，不能自动删除旧记录或启用付费资源。
- 备份独立于同步；覆盖题目、草稿、重写记录、计划和设置，保留旧备份兼容性。

“长期保留”是产品保留策略，不承诺无限免费存储或绝无故障。浏览器清除网站/扩展数据可能移除未同步的本地副本；界面应准确显示数据保存位置。

## 6. 技术职责与尚需实证的路径

- Cloudflare 网站：保留现有静态前端、Functions、D1 和隔离 Python 路径。取消邀请检查同时保留账号隔离、必要请求限额与错误提示。
- 浏览器执行：复用隔离运行器的协议；执行上下文不接收账号凭据。超时、取消、换题和迟到响应不得污染当前编辑器。
- 插件：采集、侧栏编辑、浏览器执行、本地保存；网站账号授权与同步单独接入。扩展权限与商店远程代码规则需在实施前按真实方案验证。
- 本地版：继续提供现有 Java/C++/Python 执行；浏览器端未支持的语言如实标明，不删除既有本地能力以制造一致。
- 共享部分：题目/草稿/重写数据定义、界面组件、导入规范和执行结果语义，逐批提取；不用大规模重构替代可用功能交付。
- Java/C++ 浏览器路径：只做短小可行性验证，检查编译、标准输入输出、常用库、首次加载、内存、取消、授权条件。通过前仍不计入正式支持。
- AI：用独立适配层对接用户 API；网站、插件、本地版分别验证可用调用路径。密钥不进入公开文件、普通学习备份或日志。Key 的具体存储与代理方案仍需技术设计，尚未获用户逐项审阅。
- AI 导题：真实来源题与模型原创题明确区分；没有真实检索/导入能力的模型不能凭名称伪造原题。
- 离线：本地版持续保留；网站/插件浏览器环境的资源缓存需单独完成，不能将浏览器运行直接等同于完全离线。

## 7. 建议交付顺序

### 第一批：网站的真实 Python 练习闭环

把已认可的今日、题库、练习界面接到现有真实能力，完成一条路径：导入题目 → 自己写代码 → Python 自测 → 离开回来恢复 → 重新手撕 → 对照旧代码 → 归档恢复。

同批明确草稿/重写数据结构与备份兼容，避免新记录被旧的数量保留策略清理。开放登录移除邀请门槛；验证账号隔离与数据错误时的本地恢复。已有未提交 AI/历史改动先逐项核对，合适的复用，未验证的不能混作交付。

验收使用真实网站 Python 和持久化；界面假响应不算通过。AI 自带 API 全流程、插件跨端同步不冒称在此批完成。

### 第二批：插件免本地部署

安装后无需网站登录即可在 LeetCode 侧栏采题、写 Python、运行和恢复草稿；保留重新手撕。再验证账号连接后插件与网站接续练习，并准备商店分发材料。

### 第三批：各端同步、AI 与统一发布

本地/Docker 与网站可选同步，离线冲突保留；自带 AI API 自由问答与导题；本地 Web 采用相同设计和核心功能。统一版本、更新提示、旧数据迁移及发布文档。

上述批次是内部里程碑；最终统一产品发布需给出各端实际功能对照，不能只统一版本号就宣布全部追齐。GitHub 源码、扩展包、Docker 镜像和网站需关联同一发布记录。源码许可证仍需单独确定，不擅自选择。
