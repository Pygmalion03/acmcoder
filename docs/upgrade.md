# 升级、备份与回退

本指南用于升级到 [v4.2.0](releases/v4.2.0.md)。网站、插件和 Docker 分别更新；请核对目标包的 `release-manifest.json`、提交和校验和，正式部署与镜像关联以最终发行清单为准。

## 每次升级前

1. 在「设置与数据」导出完整学习备份，保存到安装目录以外。确认文件不是空文件，并保留原包或镜像版本。
2. 网站和插件先确认当前草稿已保存。不要卸载旧插件、清除网站数据或改用另一个插件目录来代替升级。
3. 本地 / Docker 停止服务后，另存 `data/unified/`、`data/memory/`、`data/recommendation/` 的完整副本。凭据目录另行保护，不放进学习 JSON、Git 或公开安装包。

同步不能替代备份：云端删除会传播，独立备份才保留升级前的恢复点。保留升级前、升级后两份内容，便于回退后仍找回新记录。

## 网站和插件

网站在同一域名、同一浏览器空间使用本机副本。保存后刷新可进入已部署的新界面；网站不会主动刷新正在输入代码的页面。不同域名的本机存储、会话和 API Key 相互独立。正式站与保留的预览入口共用现有云端账号数据，但不能据此认为本机副本也相同。

插件从 Release 下载完整 ZIP，关闭侧栏和插件工作区，把文件更新到**原安装目录**，再在 `chrome://extensions/` 或 `edge://extensions/` 点击重新加载。保留相同身份；卸载、换目录可能使原存储不可见。源码 `extension/` 不是完整安装包；自行构建安装 `dist/extension/`。手动安装目前不使用商店自动升级。

升级后先检查原题目、当前草稿、未完成重写和历史。插件应能在网站与本地服务关闭时运行已有样例；网站需等「网站离线」显示资源就绪后再测试断网重开。

## 本地源码

保持原学习数据目录，更新源码和依赖，生成新界面，再重启服务：

```sh
npm ci --ignore-scripts
node scripts/build-clients.mjs local-web
npm start
```

`npm start` 适用于前台启动；systemd、Docker 或其他常驻服务应通过原管理器重启，不要在同一端口再启动第二个进程。本站开发环境的 `acmcoder-v3.service` 是既有服务名，不是产品版本号。

原题面和进度首次迁移时保留来源文件及 `legacy-originals/` 副本；浏览器旧语言草稿迁移后保留旧键。统一学习文件与服务端 API 应配套更新，不要只替换 `dist/local-web/` 而继续运行旧进程。

v4.2.0 将新问答按轮保存，旧聚合对话以及旧导入、恢复副本继续读取、导出和恢复，不批量改写原历史。旧客户端可能不能展示新轮记录，回退前必须导出升级后的完整备份。

## Docker

在保留原持久目录的项目中使用 v4.2.0 发行配置：

```sh
docker compose -f docker-compose.prebuilt.yml -f docker-compose.release.yml pull
docker compose -f docker-compose.prebuilt.yml -f docker-compose.release.yml up -d
```

`docker-compose.release.yml` 固定 v4.2.0；以后升级到其他版本，应使用对应发行的配置与镜像 tag。仅使用 prebuilt 文件会跟随 `latest`。`docker-compose.candidate.yml` 是旧候选环境，不用于当前正式版安装。

沿用四个持久目录和回环端口。若换了源码目录，必须确认 Compose 仍指向原数据路径；否则可能启动一个全新空工作区。不要执行删除卷或删除宿主数据目录的操作。

## 恢复到新设备

在目标设备打开设置，选择完整学习备份，先检查预览中的新增、相同和冲突数量，再确认恢复。V1/V2 旧备份和当前 V3 学习备份均可合并；这里的 V3 指数据格式，不代表只能用于某个产品版本。

确认后检查至少一道题的题面、三语言中实际使用的草稿、输入、重写快照、运行记录和对话；刷新或重开后再次查看。再次导入相同备份应跳过相同记录。已有不同内容会保留原记录并进入冲突处理区，可另存副本，不静默覆盖。

已经彻底删除的题目从旧备份恢复时需另存新 ID，旧设备不能复活原 ID。连接账号后还应等待同步状态完成；导入成功不等同于云端同步成功。API Key 和设备授权不在学习备份中，目标设备需要重新配置或授权。

## 回退

1. 先导出升级后的学习备份，停止当前服务或关闭插件页面，保留当前数据目录。
2. 使用升级前保留的包或固定镜像；本地 / Docker 挂载**升级前的数据副本**，不要让旧程序直接覆盖唯一的新数据目录。
3. 核对原题目、草稿和历史，再决定是否恢复日常使用。升级后新增的内容继续保存在独立备份中，待兼容客户端合并恢复。

网站升级到 v4.2.0 需配套执行 `0007_record_capacity_repair.sql`，修复容量统计并保留同步日志和删除标记。执行前保存数据库恢复点，按现有迁移顺序应用并记录结果。网站回退使用旧的不可变 Pages 部署；D1 数据迁移和应用部署分别管理，不通过删除迁移表、删除 tombstone 或手工倒改计数回退。

本次功能与验证见 [v4.2.0 说明](releases/v4.2.0.md)。历史验收保持原版本与日期，见 [v4.2.0 说明](releases/v4.2.0.md)、[正式升级回执](releases/evidence/v4-stable-2026-10-02.json)和[本次本机数据验收](releases/evidence/stage-c-2026-10-24.json)。
